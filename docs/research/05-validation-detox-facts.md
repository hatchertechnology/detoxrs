## Verdict vocabulary and evidence labels

Verdicts (used consistently across docs 05, 06, 07):

| Verdict        | Meaning                                                                     |
| -------------- | --------------------------------------------------------------------------- |
| `CONFIRMED`    | Claim verified true as written.                                             |
| `REFINED`      | Claim true in substance, but needs a caveat, correction, or narrowing.      |
| `REFUTED`      | Claim false, or backwards.                                                  |
| `SUPERSEDED`   | Was right when written; later work has since improved on it. `[stage-3]`    |
| `UNVERIFIED`   | Not checked in any pass. No opinion offered.                                |
| `UNVERIFIABLE` | Cannot be checked with the hardware/access available; reason stated inline. |

This document originally used `PARTIALLY REFUTED`, which docs 06 and 07 spell `REFINED`. The
two rows carrying it (R4, R21) keep the original words with the shared term appended, so old
citations still match the text they quoted.

Every evidence cell carries a strength label, because doc 00 weights these very differently:

- `[MEASURED]` — measured on this hardware, in this session, against a real binary or filesystem.
- `[SOURCE]` — read from source code or a spec. Not behavioral.
- `[WEB]` — fetched from a live API or official documentation page.
- `[SECONDARY]` — from a blog, Q&A thread, or search summary; primary fetch failed or absent.
- `[INHERITED]` — carried over from an earlier pass without re-verification.
